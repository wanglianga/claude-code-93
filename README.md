# 建设银行网点排队叫号与适老服务预约平台

> 技术栈：Vue 3 + Vite（前端） · Spring Boot 3 + Spring Security/JWT + JPA（后端） · PostgreSQL 16（数据库） · Nginx（静态托管/反代） · Docker Compose 一键部署

## 原始需求

建设银行网点排队叫号与适老服务预约平台，可采用 Vue 3、Spring Boot 和 PostgreSQL。客户到网点办理开户、转账、挂失、社保卡、理财咨询或大额现金业务时，平台记录客户类型、预约来源、业务类型、风险等级、是否老人、轮椅或听力引导需求和预计办理时长。大堂经理根据客户材料完整度、柜员技能、现金库存、理财经理排班和窗口负载进行分流。老人预约服务时，平台可安排陪同引导、优先窗口、材料预审和家属远程确认。若客户长时间等待、大额转账触发反诈核验、老人忘带证件、柜员临时离岗、自助机故障或客户投诉插队，平台要把大堂经理、柜员、理财经理、安保、客服和客户放在同一排队记录中处理。办理结束后，等待时长、业务结果、风险提示、投诉和回访进入网点运营档案。平台还要处理现金业务、反诈拦截、无障碍通道、养老金集中发放日和网点突发停电。银行网点排队既涉及服务效率，也涉及合规审核和老人安全。平台还要记录客户是否被引导到正确渠道，比如柜台、自助机、理财室或远程客服，避免所有业务都挤压柜台窗口。

## 一、功能与角色

平台围绕**同一条排队记录（Ticket）**组织六方协同：**大堂经理、柜员、理财经理、安保、客服、客户**。

| 角色 | 账号 | 主要权限/视图 |
|---|---|---|
| 客户 | `customer01` | 线上取号、适老服务预约（陪同引导/优先窗口/材料预审/家属远程确认/轮椅/听力引导）、查看排队进度与处理时间线、取消排队 |
| 大堂经理 | `manager` | 网点 KPI 看板、材料完整度登记、**渠道智能推荐与分流**（柜台/自助机/理财室/远程客服）、窗口负载与柜员技能调度、现金库存查看与调拨、未闭环事件协调、养老金日/突发停电应急 |
| 柜员 | `teller01` / `teller02` / `teller03` | 本窗口叫下一位、指定号码叫号、爱心窗口优先、临时离岗/回岗/设备故障、办结（业务结果+风险提示+投诉记录） |
| 理财经理 | `advisor01` | 理财室排队、理财咨询叫号、双录完成办结 |
| 安保 | `security01` | **大额转账反诈核验**（通过放行 / 拦截劝阻）、无障碍通道迎接任务、自助设备故障与停电上报 |
| 客服 | `service01` | 投诉插队受理、长等客户关怀、办结客户回访（写入运营档案）、远程渠道引导 |

> 统一演示密码：**`ccb@123456`**（登录页点击账号可自动填充）

### 核心业务规则

- **取号/预约信息**：客户类型（普通/VIP/老年/对公）、预约来源（现场/手机银行/电话/老年热线）、业务类型（开户/转账/挂失/社保卡/理财咨询/大额现金）、风险等级、老人/轮椅/听力标记、预计办理时长、金额。
- **分流防挤兑**：系统按业务类型、风险等级、是否老人、金额、材料完整度推荐渠道——标准业务（开户/转账/社保卡）引导自助机，理财咨询进理财室，挂失/大额现金/高风险/老人走柜台，缺材料先进远程客服/预审；经理可强制改派到指定窗口与处理人。
- **适老服务**：老人自动建议爱心优先窗口；支持陪同引导、材料预审、家属远程确认（登记家属联系方式）；忘带证件时单据挂起进入预审/家属确认流程，不占用窗口。
- **异常六方协同**（全部沉淀在同一记录的时间线上）：
  - 长时间等待：系统每 30 秒扫描（演示阈值 10 分钟），自动生成预警事件，经理/客服安抚优先安排；
  - 大额转账（≥ 5 万元）：柜员叫号即触发**反诈核验**，单据挂起，安保核验通过后自动恢复办理、拦截则记录并按拒绝/升级办结；
  - 老人忘带证件：挂起 + 预审 + 家属远程确认；
  - 柜员临时离岗：窗口置离岗、在办单挂起回池重新分流；
  - 自助机故障：设备置故障、客户改引柜台；
  - 投诉插队：客服在同一记录登记投诉并介入；
  - 网点突发停电：经理/安保一键触发应急预案，全部在办/待叫单据挂起，恢复后自动重新入队。
- **现金业务**：大额取现校验现金库存，不足自动发起调拨；办结成功扣减库存，低于预警线看板告警。
- **养老金集中发放日**：可一键标记/解除，全网点横幅提示（老年客户激增、增开爱心窗口、加强备付与维序）。
- **运营档案**：办结后记录实际等待时长、业务结果（成功/拒绝/升级/转渠道）、风险提示、投诉与回访；提供渠道引导分布图、结果统计、平均等待、反诈拦截数、回访覆盖率。

## 三、快速启动（宿主 Docker Compose，一键部署）

前置：宿主已安装 Docker Engine 与 Docker Compose 插件。

```bash
cd 93-b
cp .env.example .env          # 可按需要改 CC_PUBLISH_PORT（宿主端口）
docker compose up -d --build  # 构建并启动 db / app / web 三个服务
docker compose ps             # 等待 app、web 健康（healthy）
```

仅 **web 门户端口发布到宿主**（`CC_PUBLISH_PORT:8080`）；PostgreSQL 与后端端口均不对外暴露，只在 compose 内部网络通过服务名 `db`、`app` 互访。

获取实际访问地址（避免依赖固定端口）：

```bash
docker compose port web 8080    # 例如 0.0.0.0:3193
# 浏览器打开 http://<宿主IP>:3193 （本机即 http://localhost:3193）
```

健康检查：

```bash
curl -fsS http://localhost:${CC_PUBLISH_PORT}/actuator/health
# {"status":"UP"}
```

停止与清理：

```bash
docker compose down            # 停止并删除容器（保留数据卷）
docker compose down -v         # 同时清空数据库卷，下次启动重新播种演示数据
```

## 四、建议的演示走查路径（端到端）

1. **客户** `customer01` 登录 → 提交一笔「老人 + 大额转账 80000 + 家属远程确认」预约；再提交一笔普通「开户」。
2. **大堂经理** `manager` 登录 → 看待分流队列，点单据「获取渠道推荐」→ 普通开户被推荐到**自助机**、大额老人单推荐到**柜台（优先窗口）**→ 确认分流；对缺材料老人登记「缺失」触发忘带证件流程。
3. **柜员** `teller03`（爱心窗口）登录 → 叫号大额转账单 → 系统提示**触发反诈核验、单据挂起**。
4. **安保** `security01` 登录 → 反诈队列中填写核验意见 → 「通过·恢复办理」（或对可疑单「拦截·劝阻」）。
5. 回到**柜员** → 办结，填写业务结果与风险提示；在另一张单上演示「临时离岗」（经理看板可见挂起单并重新分流）。
6. **大堂经理/安保** → 触发「突发停电」，全部在途单挂起；再「供电恢复」，单据自动回队。
7. 对等待较久的单，**客服** `service01` 受理「投诉插队」；办结后在「投诉/回访」页填写回访。
8. 打开「运营档案」页：查看等待时长、结果、风险提示、投诉、回访、渠道引导分布与反诈拦截统计。

## 五、目录结构

```

├── docker-compose.yml          # db(postgres) + app(springboot) + web(nginx+vue)
├── .env.example

│   ├── pom.xml

│       ├── security/                 # JWT + Spring Security

│       └── web/                      # AuthController / QueueController / 异常处理

    ├── Dockerfile              # 多阶段：node 构建 → nginx 托管（非 root + HEALTHCHECK）
```

## 六、配置项（环境变量）

| 变量 | 默认值 | 说明 |
|---|---|---|
| `CC_PUBLISH_PORT` | `3193` | 发布到宿主的 web 门户端口 |
| `JWT_SECRET` | 内置演示值 | JWT 签名密钥，生产请更换 |
| `SPRING_DATASOURCE_URL` | `jdbc:postgresql://db:5432/branch_queue` | compose 内数据库地址 |
| `SPRING_DATASOURCE_USERNAME/PASSWORD` | `ccb / ccb_pass` | 数据库账号 |

应用侧业务参数（`backend/src/main/resources/application.yml`，可按需调整）：长等阈值 `app.queue.long-wait-seconds=600`、大额阈值 `app.queue.large-amount-threshold=50000`。
