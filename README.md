# 建设银行网点排队叫号与适老服务预约平台

Vue 3 + Spring Boot 3 + PostgreSQL，单镜像交付（前端构建产物打入 Spring Boot 静态资源），
`docker compose up -d` 一键部署。平台围绕「一条排队记录」把大堂经理、柜员、理财经理、
安保、客服与客户串在同一业务流中，兼顾服务效率、合规审核与老人安全。

## 原始需求

建设银行网点排队叫号与适老服务预约平台，可采用 Vue 3、Spring Boot 和 PostgreSQL。客户到网点办理开户、转账、挂失、社保卡、理财咨询或大额现金业务时，平台记录客户类型、预约来源、业务类型、风险等级、是否老人、轮椅或听力引导需求和预计办理时长。大堂经理根据客户材料完整度、柜员技能、现金库存、理财经理排班和窗口负载进行分流。老人预约服务时，平台可安排陪同引导、优先窗口、材料预审和家属远程确认。若客户长时间等待、大额转账触发反诈核验、老人忘带证件、柜员临时离岗、自助机故障或客户投诉插队，平台要把大堂经理、柜员、理财经理、安保、客服和客户放在同一排队记录中处理。办理结束后，等待时长、业务结果、风险提示、投诉和回访进入网点运营档案。平台还要处理现金业务、反诈拦截、无障碍通道、养老金集中发放日和网点突发停电。银行网点排队既涉及服务效率，也涉及合规审核和老人安全。平台还要记录客户是否被引导到正确渠道，比如柜台、自助机、理财室或远程客服，避免所有业务都挤压柜台窗口。

## 功能与需求对照

| 需求点 | 实现 |
| --- | --- |
| 六类业务、客户类型、预约来源、风险等级、老人/轮椅/听力、预计时长 | 「排队分流」页取号登记表单全量采集，进入 `queue_ticket` |
| 材料完整度 / 柜员技能 / 现金库存 / 理财经理排班(窗口) / 窗口负载分流 | 「智能分流」自动给出渠道+窗口+理由：优先窗、理财室 L1、智能柜员机 M1/M2、现金柜台 W1，按技能与 `currentLoad` 选最低负载窗口 |
| 陪同引导 / 优先窗口 / 材料预审 / 家属远程确认 | 「适老预约」页：预约 → 安排陪同人 → 家属视频确认 → 到店自动高优先级取号并入敬老优先窗 |
| 长等待 | 后端每 60 秒巡检，等待 ≥20 分钟自动产生「长时间等待」事件并提升优先级 |
| 大额转账反诈核验 | ≥20 万元自动 HIGH 风险并生成反诈事件；反诈四问通过才能办结，或执行拦截劝阻归档（合规闸门） |
| 老人忘带证件 | 协同事件类型，材料分降至 40，一次性告知/家属递送/改约 |
| 柜员临时离岗 / 自助机故障 | 窗口置 BREAK/FAULT 自动生成事件；故障机具上的客户自动改派普通柜台；处置后窗口恢复 |
| 投诉插队 | 事件登记投诉，被影响客户优先级 +15，客服处置，投诉随档留痕 |
| 运营档案 | 办结自动归档：等待时长、办理时长、业务结果、风险提示、投诉、回访满意度、渠道是否正确 |
| 现金业务 | 大额现金校验库存，办结扣减；库存不足生成调拨事件；库存不足无法办结 |
| 反诈拦截 | 一键拦截 → 业务终止并归档留痕，联动关闭反诈事件 |
| 无障碍通道 | 轮椅/听力标记、坡道提示、敬老优先窗 P1、陪同引导事件 |
| 养老金集中发放日 | 看板一键开启：老人/养老金客户优先级加权到 80，产生高峰事件提示增窗加岗 |
| 网点突发停电 | 停电应急模式：挂起电子队列、停止叫号分流、安保事件；恢复后自动解挂并关单 |
| 渠道正确性 | 档案自动判断本可自助的开户/小额转账是否被错误引到柜台，看板统计「渠道可优化」 |
| 叫号大屏 | 免登录 `/board`：正在呼叫、候场队列（敬老高亮）、窗口状态，5 秒刷新 |

## 技术架构

```
浏览器 ──► Nginx? 否：Spring Boot 单进程
Vue3 + Element Plus  ──build──►  拷贝进 backend/src/main/resources/static
                                      │
                 Spring Boot 3.3 (Java 17, JPA, Actuator)
                                      │ docker 内网  db:5432
                                 PostgreSQL 16
```

- 后端端口 8080，actuator 健康检查 `/actuator/health`，容器以非 root 用户 `app(uid=1001)` 运行。
- 令牌鉴权：登录返回 token，前端以 `X-Auth-Token` 携带；叫号大屏与字典接口免登录（演示用内存 TokenStore）。
- JPA `ddl-auto=update`，首启 `DataInitializer` 写入演示账号、窗口、库存与样例数据。

## 快速开始（宿主 docker compose 验证）

```bash
cp .env.example .env        # CC_PUBLISH_PORT 可按环境修改（默认 3093）
docker compose up -d --build
docker compose ps
# 健康检查
curl -s http://localhost:${CC_PUBLISH_PORT}/actuator/health
# 浏览器打开
#   http://<宿主IP>:3093/        工作台（登录）
#   http://<宿主IP>:3093/#/board 叫号大屏（免登录）
docker compose down          # 验证结束释放资源（加 -v 同时清库）
```

> 仅应用端口发布到宿主：`${CC_PUBLISH_PORT}:8080`；PostgreSQL 不发布宿主端口，
> 仅在 compose 内网通过服务名 `db` 访问。验证时取实际映射端口：
> `docker compose port app 8080`。

## 建议业务流验证路径

1. 用 `manager01` 登录 → 运营看板查看队列/窗口负载/渠道分布。
2. 排队分流：对「王海燕 50 万转账」点【反诈】→ 四问通过（或拦截）；
   对「张建国」点【智能分流】→ 系统建议智能柜员机。
3. 窗口叫号（teller01 / teller04）：呼叫下一位 → 确认到窗 → 办结归档。
4. 适老预约：安排田秀珍（陪同人+优先窗+家属确认）→ 到店取号 → 自动进入 P1。
5. 协同事件：登记「柜员临时离岗」「自助机故障」「投诉插队」「老人忘带证件」并处置。
6. 运营看板：打开「养老金集中发放日」观察老人单优先级变化；打开「停电应急」验证队列挂起/恢复。
7. 运营档案：查看等待时长、风险提示、投诉留痕，登记回访满意度。
8. 浏览器开 `/#/board` 看叫号大屏。
